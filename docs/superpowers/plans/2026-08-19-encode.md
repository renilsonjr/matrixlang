# `encode` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `encode`, a unary keyword converting a number to text — the mirror of `decode` — so a program can print a number inside a sentence.

**Architecture:** `encode` reuses the existing `Unary` node with a new `TokenType`, exactly as `decode`, `length` and `unplug` do, so no new node type is needed. It sits at the parser's `_unary` precedence level beside `decode`. Its output comes from `values.to_display`, the function `trace` already uses, so the language keeps one answer to "how does a number look". Both textual faces and the `parse` tree view gain an entry, and the glyph budget's hand-tracked counts move by one.

**Tech Stack:** Python 3.11+ stdlib, pytest. No new dependencies, no JavaScript, no build step.

## Global Constraints

- The keyword is **`encode`** — single word, no underscore, like every other keyword (EN-1).
- **Numbers only, strictly** (EN-2). Booleans, lists, functions and text-already-text all error.
- **Output is exactly what `trace` prints** (EN-4): `42` → `"42"`, `-3` → `"-3"`, `0` → `"0"`. Reach `values.to_display`; do not format integers separately.
- **Precedence is the `_unary` level**, beside `decode` and `length` — `encode n + 1` is `(encode n) + 1` (EN-5).
- **Reuses `Unary` with `TokenType.ENCODE`** — no new node type (EN-6).
- **No implicit coercion** (EN-7). `"ID: " + 1` stays an error.
- Keywords 16 → 17, glyph slots 43 → 44, free 13 → 12 (EN-8).
- `src/matrixlang/lexer.py`, `nodes.py`, `scribe.py`, `input.py`, `site/glue.py` and every `site/*.js` are **untouched** (EN-9).
- `site/checks/no_semantics.py` and `key_handling.py` pass **unmodified** — there are no JavaScript changes at all.
- `tests/test_architecture.py` needs **no** change: no new module, and `interpreter` already imports `values`.
- Run tests from the repo root as `PYTHONPATH="$PWD/src" python3 -m pytest ... -q`. Use `python3`, not `python`.

def _run(source_text: str) -> list[str]:
    import io

    from matrixlang.interpreter import Interpreter
    from matrixlang.lexer import lex
    from matrixlang.parser import parse

    out = io.StringIO()
    Interpreter(out=out).run(parse(lex(source_text)))
    return out.getvalue().splitlines()


def test_encode_turns_a_number_into_text():
    assert _run('trace "ID: " + encode 42\n') == ["ID: 42"]


def test_encode_handles_negatives_and_zero():
    assert _run('trace encode -3 + "/" + encode 0\n') == ["-3/0"]


def test_encode_agrees_with_what_trace_prints():
    # One answer to "how does a number look", not two. If encode ever
    # formats integers itself, this is what catches the divergence.
    for n in ["0", "7", "-3", "1000", "-1000"]:
        (encoded,) = _run(f"trace encode {n}\n")
        (printed,) = _run(f"trace {n}\n")
        assert encoded == printed, f"encode {n} disagreed with trace {n}"


def test_decode_of_encode_returns_the_number():
    # The round-trip invariant. The REVERSE does not hold -- decode
    # tolerates whitespace and a leading sign, so it is many-to-one --
    # and the design doc says so; do not add the symmetric test.
    for n in ["0", "7", "-3", "1000"]:
        assert _run(f"trace decode encode {n}\n") == [n]


def test_encode_rejects_text():
    from matrixlang.errors import MatrixLangError

    with pytest.raises(MatrixLangError) as caught:
        _run('trace encode "already text"\n')
    assert "'encode' takes a number, got text" in caught.value.message


def test_encode_rejects_a_boolean():
    # Strict like splice, which refuses a non-boolean rather than coercing.
    from matrixlang.errors import MatrixLangError

    with pytest.raises(MatrixLangError) as caught:
        _run("trace encode true\n")

def test_encode_rejects_a_list():

def test_adding_a_number_to_text_is_still_an_error():
