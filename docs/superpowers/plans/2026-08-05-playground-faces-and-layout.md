# Playground Faces and Layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the live playground a desktop layout (editor beside the cascade, examples two-up), a three-state layout switch that persists, and on-demand glyph/Latin faces for the cascade, the examples, and the editor.

**Architecture:** Pure CSS layout keyed off `data-layout` on `<html>`, with the wide band stated exactly once via a custom-property flag consumed by a single `@container style()` rule. A new `site/layout.js` owns the switch and its `localStorage` persistence and applies it before first paint. Face selection is wiring: `sse.payload` already ships `source`/`latin` for statements and `glyphs`/`text` for output; `playground.js` picks the pair by a `face` variable, and the editor's glyph face is rendered by Python (`render_glyph`) because the browser may draw but must not transliterate.

**Tech Stack:** Python 3.11+ stdlib, pytest, plain HTML/CSS/JS. No new dependencies, no build step beyond the existing assembly in `.github/workflows/pages.yml`.

## Global Constraints

- `src/matrixlang/` and `server/sse.py` are **untouched** (FL-10). Both faces already exist on the wire; no new payload field is added.
- `site/checks/no_semantics.py` still passes: no toggle transliterates or untransliterates in JavaScript. Every face rendered on the page is a string Python already rendered (`render_glyph`/`render_ascii`).
- `site/checks/key_handling.py` still passes **unmodified** (FL-5): `playground.js` gains no persistence sink. The `localStorage` preference lives only in the new `site/layout.js`, which touches no credential.
- The full test suite stays green: existing 1,382 tests + new ones.
- The cascade keeps an explicit `aspect-ratio: 16 / 9`. Any new wide-layout height rule must give the canvas a height that does not depend on `canvas.width`/`canvas.height` attributes (the `ResizeObserver` feedback loop from the first playground bug).
- The five examples are still "shipped executed": `site/examples.json` is generated and CI-freshness-checked; a new `glyph` field per example is generated by `render_glyph`, never typed by hand.
- The two rules that reach the wide layout must produce the same result — the wide band is stated **once** and referenced, never duplicated, so the media query and the forced-desktop override cannot drift.

- [ ] **Step 3: Write `site/layout.js`**

```javascript
// site/layout.js
// The layout switch. Lives apart from playground.js on purpose: it touches
// localStorage, and playground.js handles the reader's API key, which must
// never be persisted. site/checks/key_handling.py stays scoped to
// playground.js and is not loosened.

const STORAGE_KEY = "matrixlang-layout";
const VALID = ["auto", "desktop", "mobile"];

function readPref() {
  try {
    const stored = localStorage.getItem(STORAGE_KEY);
    return VALID.includes(stored) ? stored : "auto";
  } catch {
    return "auto"; // storage blocked (private mode) — fall back, never crash
  }
}

function writePref(value) {
  try {
    localStorage.setItem(STORAGE_KEY, value);
  } catch {
    /* storage blocked — the in-memory attribute still applies for this visit */
  }
}

// Before first paint: the stored preference decides, so a Desktop reader
// never sees the mobile layout flash. Runs synchronously because this file
// is loaded in <head> ahead of the stylesheet.
document.documentElement.dataset.layout = readPref();

// The buttons live in the body, which is not parsed yet — wire them when it
// is. Until then the attribute above is already doing the work.
document.addEventListener("DOMContentLoaded", () => {
  const buttons = document.querySelectorAll("[data-layout-choice]");
  for (const button of buttons) {
    button.addEventListener("click", () => {
      document.documentElement.dataset.layout = button.dataset.layoutChoice;
      writePref(button.dataset.layoutChoice);
      sync();
    });
  }
  sync();

  function sync() {
    const current = document.documentElement.dataset.layout;
    for (const button of buttons) {
      const active = button.dataset.layoutChoice === current;
      button.classList.toggle("active", active);
      button.setAttribute("aria-pressed", String(active));
    }
  }
});
```

- [ ] **Step 6: Write the wide band in `site/style.css` — stated once**

Append a layout section. One `@container style()` block is the **only** place the wide band is written; the media query and the attribute just flip the `--layout` flag on `:root`, so the two routes cannot drift:

```css
/* ---- the layout band ---- */

:root {
  /* The layout switch. `--layout` is the single flag both the media query
     and the [data-layout] override flip; @container style() consumes it
     below, so the wide band is written once. */
  container-type: style;
  --layout: mobile;
}

/* Auto: the viewport decides, unless the reader is pinned to Mobile. */
@media (min-width: 60rem) {
  :root:not([data-layout="mobile"]) { --layout: desktop; }
}
/* Forced: Desktop wins regardless of width, Mobile loses the media query. */
:root[data-layout="desktop"] { --layout: desktop; }

/* THE wide band — written exactly once. */
@container style(--layout: desktop) {
  .band { max-width: none; }
  .examples {
    grid-template-columns: 1fr 1fr;
    gap: 1.75rem;
  }
  .playground-grid {
    display: grid;
    grid-template-columns: minmax(0, 1fr) minmax(0, 1.4fr);
    gap: 1.75rem;
    align-items: start;
  }
}
```

```python
def glyph(source: str) -> dict:
    """The glyph face of arbitrary source, rendered by Python. Never raises.

    The editor toggle shows this face *beside* what the reader typed; it
    never rewrites the editor. Rendering happens here rather than in
    JavaScript because the browser may draw but must not own the
    transliteration table (§5.7, site/checks/no_semantics.py).
    """
    try:
        program = parse(lex(source))
    except MatrixLangError as error:
        return {"ok": False, "error": f"[line {error.line}, column {error.column}] {error.message}"}
    return {"ok": True, "glyph": render_glyph(program)}
```

(`MatrixLangError` is already imported inside `run`; reuse that same import.)

function toggleCascadeFace() {
  face = face === "glyph" ? "latin" : "glyph";
  const button = el("cascade-face");
  button.textContent = face === "glyph" ? "Latin" : "Glyph wall";
  // Applies to the next run: the wall is cleared per run by design, and
  // toggling mid-fall would need cascade.js to re-render its history —
  // presentation, not worth touching the copied file for.

function toggleEditorFace() {
  const pre = el("editor-glyph");
  const button = el("editor-face");
  if (pre.hidden === false) {
    pre.hidden = true;
    button.textContent = "Show glyphs";
    return;
  }
  // Ask Python, never transliterate here. A parse failure shows the real
  // diagnostic in the shared miss slot rather than a broken face.
  const result = glue.glyph(el("editor").value).toJs({ dict_converter: Object.fromEntries });
  if (result.ok) {
    pre.textContent = result.glyph;
    pre.hidden = false;
    button.textContent = "Hide glyphs";
  } else {
    el("miss").textContent = result.error;
    el("miss").hidden = false;
  }
}

function toggleExampleFace(button) {
  const pre = button.previousElementSibling;
  pre.hidden = pre.hidden === false;
  button.textContent = pre.hidden ? "Show glyphs" : "Hide glyphs";
