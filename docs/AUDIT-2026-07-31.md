# Audit findings — 2026-07-31

An independent read of the repository at `e1af9a1`, checking the code against
what `README.md` and `docs/TECHNICAL-OVERVIEW.md` claim about it.

Every finding below was reproduced, and the reproduction is included. Where a
claim could not be tested in this environment it says so rather than asserting.

**Baseline.** `753 tests pass`. The suite was run with `PYTHONPATH=src python3
-m pytest` on Python 3.10 — the only interpreter available here — rather than
through an editable install. `pyproject.toml` declares `requires-python =
">=3.11"`; the package in fact imports and passes its whole suite on 3.10, so
that floor is conservative rather than wrong.

Findings are ordered by consequence, not by module.

---

## 1. The transliteration table is not reversible for all text

**Severity: high — a documented invariant is false, and a program can reach it.**

`src/matrixlang/translit.py:11-14` states the module's purpose:

> **Reversibility is the point.** [...]
> `untransliterate(transliterate(text)) == text` for ALL text

It does not hold. The guarantee rests on decision 2 in that same docstring —
"uncovered characters pass through unchanged, and that is still reversible,
[because] the glyph alphabet is disjoint from ASCII". The disjointness argument
covers ASCII input. It says nothing about input that is *already* a glyph, and
`transliterate` passes those through untouched (`translit.py:84`) straight into
a decoder that reads them as encoded (`translit.py:96`).

```
$ PYTHONPATH=src python3 -c "
from matrixlang.translit import transliterate, untransliterate, SHIFT
for t in ['ｱ', 'ｦ', SHIFT]:
    print(repr(t), '->', repr(untransliterate(transliterate(t))))"
'ｱ' -> 'g'
'ｦ' -> '0'
'ﾙ' -> ''
```

Any of the 61 characters in U+FF61–FF9D round-trips to the wrong thing, and the
SHIFT marker (`ﾙ`) round-trips to nothing at all while uppercasing whatever
follows it.

**It is reachable from a `.rain` file.** The lexer accepts any non-control
character inside a string literal, so a glyph in a string reaches the cascade:

```
$ printf 'trace "ｱ"\n' > kata.rain
$ PYTHONPATH=src python3 -m matrixlang run --no-window kata.rain
ｱ
$ PYTHONPATH=src python3 -c "
from random import Random
from matrixlang.cascade import CascadeField
from matrixlang.events import Output
from matrixlang.translit import untransliterate
f = CascadeField(80, 30, Random(1)); f.consume(Output(text='ｱ', line=1))
print(f.transcript(), [untransliterate(t) for t in f.transcript()])"
['ｱ'] ['g']
```

The program printed `ｱ`; the cascade shows `ｱ`; a reader decoding the screen with
the published table gets `g`. That is precisely the property the module exists
to provide — "an LLM handed this table and a line of glyphs can recover the
text" (`translit.py:102-108`) — and it silently produces a wrong answer rather
than refusing.

`tests/test_translit.py` tests round-tripping over ASCII, letters, digits,
punctuation and case, but never over a character drawn from the output alphabet
itself. The invariant is asserted only across inputs that cannot violate it.

**Two ways out.** Either narrow the claim to "all text over the covered
alphabet plus non-glyph passthrough", and have `transliterate` reject or mark
input containing pool characters; or spend a marker glyph on literal-passthrough
the way SHIFT is spent on case. The first is smaller and matches how the lexer
handles the analogous problem — refuse at the boundary rather than escape
downstream (`docs/TECHNICAL-OVERVIEW.md` §6).

## 2. Window mode freezes and grows without bound on a loop

**Severity: high — the window is unusable for exactly the programs the language
advertises.**

Three pieces combine.

`window.drain` (`src/matrixlang/window.py:46-62`) loops until the queue is
empty, with no per-frame budget. It is called from `step()` (`window.py:143`),
which is called from `_tick()` (`window.py:162`), which is the UI thread's
frame callback. `CascadeField.add` (`cascade.py:120-124`) appends to both
`_waiting` and `_history`, and `_history` is never trimmed — by design, so a
finished program can replay (`cascade.py:167-179`). The interpreter emits one
`Statement` event per statement *per iteration* (`interpreter.py:75`).

So the queue drains only as fast as the field can consume, the field retains
everything forever, and the UI thread is the one doing the consuming.

**Measured, on this machine:**

| | rate |
| --- | --- |
| interpreter emits | ~442,000 events/sec |
| `field.consume` absorbs | ~178,000 events/sec |
| lines that actually reach the screen | ~72 lines/sec |
| retained per event | 216 bytes |

Production outruns consumption by ~2.5×, so the queue never empties while a
program runs, so `drain()` does not return, so no frame is ever drawn. A single
`drain()` call, measured against a program executing 400,000 statements:

```
single drain() call took 17.94s   (frame budget is 0.033s)
program still running when drain returned: False
queue left: 0  waiting lines: 400002  history: 400002
backlog would take ~5556s (92.6 min) to finish falling
```

The drain returned only when the program ended. For 18 seconds the UI thread was
inside one frame callback: nothing redraws, `after()` is never rescheduled, and
the window is what an operating system calls unresponsive. For a genuinely
unbounded loop it never returns at all.

The memory side is linear and unbounded: at 216 bytes/event and ~442k events/sec,
a `dejavu` loop grows the field by roughly **95 MB per second** of execution.

And even after the program ends, the backlog is absurd: 18 seconds of computation
produced 93 minutes of falling material, all of it retained in `_history` so the
loop replays it forever.

This collides directly with the README's own framing:

> That is not a sandbox [...] Two things it deliberately does not cover: a
> program can loop forever, which is what Turing-completeness means

Looping forever is documented as acceptable. In window mode it hangs the window
and exhausts memory, which is a different outcome from "it loops".

**Direction.** The three fixes are independent and any one of them helps:
give `drain()` a bounded budget per frame (drain N events, or until a deadline,
then return so `_tick` can redraw); cap `_waiting` and `_history` with a ring
buffer, since material beyond a few screens' worth cannot be read anyway; and
consider coalescing `Statement` events for a line already in flight.

Note the split that makes this testable at all is the right one — the whole
measurement above ran without Tk, because `cascade.py` is pure. The purity
gradient described in §5.6 of the technical overview did its job; the frame
budget is simply a requirement nobody wrote down.

## 3. `run` exits 0 for a program that never finished

**Severity: medium — a wrong exit code, in the one mode that has no other signal.**

`src/matrixlang/cli.py:186-187`:

```python
worker.join(timeout=1.0)
return outcome[0] if outcome else 0
```

`outcome` is appended by the worker thread when execution finishes, one way or
the other. If the viewer closes the window while the program is still running —
the expected way to stop a long program, given the window is the output device —
`mainloop()` returns, the join times out, `outcome` is empty, and the CLI
reports success for a run that was abandoned partway.

Reproduced with the project's own fake-window pattern from `tests/test_cli.py`:

```python
class ClosedEarlyWindow:          # a viewer who closes it at once
    ...
    def mainloop(self): return

def test_closing_the_window_early_reports_success(...):
    path.write_text("construct n = 0\ndejavu n < 3000000\n  n = n + 1\n"
                    "flatline\ntrace nope\n")
    ...
    assert main(["run", str(path)]) == 1
```

The program's last statement is a guaranteed runtime error, so a completed run
must exit 1.

```
AssertionError: exited 0: success reported for an unfinished run
```

`tests/test_cli.py` covers a runtime error in the window (exit 1), a window that
fails to open (falls back to text), and Ctrl-C during `mainloop` (exit 130). It
does not cover the viewer closing the window early, which is the ordinary case.

**Direction.** Distinguish "did not finish" from "finished successfully" — 130
matches the Ctrl-C convention already used two lines above, or a distinct code
if abandonment should be told apart from interruption. The `_closed` flag set by
`CascadeWindow.close()` would be a natural carrier, which brings up finding 8.

## 4. Two of the four shipped web samples cannot run

**Severity: medium — the first thing a visitor clicks is broken.**

`web/app.js` ships four samples in the picker. `counter` and `fibonacci` both
use `string + integer`:

```
trace "Processing frame: " + count
trace "Fib: " + a
```

The language has no implicit stringification — `docs/TECHNICAL-OVERVIEW.md` §4
lists it as a deliberate semantic — and *both* implementations enforce it, so
selecting either sample and pressing RUN produces an immediate error:

```
===== counter =====
python: matrixlang: [line 9, column 32] cannot add string and integer   [exit 1]
js:     JSERROR: Cannot add string and number                           [exit 1]
```

```
===== fibonacci =====
python: matrixlang: [line 8, column 17] cannot add string and integer   [exit 1]
js:     JSERROR: Cannot add string and number                           [exit 1]
```

`hello` and `glyphs` both run and agree across implementations. So this is not a
subtle divergence — it is two demo programs written against a language feature
that does not exist. `trace "Fib: "` followed by `trace a` is the fix, or a
string-conversion builtin if concatenating values is wanted (which would be a
language change, not a sample fix).

## 5. The web interpreter is a second, divergent implementation

**Severity: medium — silently different answers, with no test to notice.**

`web/interpreter.js:1-4` describes itself as a "full parser, lexer, and
interpreter matching MatrixLang v0.5.0 spec". It is a genuine reimplementation,
not a port, and it disagrees with the reference in ways that mostly produce
*wrong values* rather than errors.

Differential run of 26 programs through both. Cases where the two agree are
omitted; error-message wording differences are omitted as expected.

| program | Python | JavaScript |
| --- | --- | --- |
| `trace -7 / 2` | `-3` | **parse error: "Unexpected expression token '-'"** |
| `trace true - 1` | error: left operand must be an integer | **`0`** |
| `trace "a" < "b"` | error: left operand must be an integer | **`true`** |
| `trace "a" * 2` | error: left operand must be an integer | **`NaN`** |
| `trace true == 1` | error: cannot compare boolean with integer | **`false`** |
| `trace "1" == 1` | error: cannot compare string with integer | **`false`** |
| `trace 9007199254740993` | `9007199254740993` | **`9007199254740992`** |
| `construct a = 999999999999` `trace a * a` | `999999999998000000000001` | **`9.99999999998e+23`** |
| `trace "a\nb"` | `a`, newline, `b` | **`a\nb` literally** |
| `trace "a\qb"` | error: unknown escape sequence | **`a\qb`** |

Five things worth separating out.

**5a. There is no unary minus.** `parsePrimary` (`web/interpreter.js:383-397`)
has branches for NUMBER, STRING, BOOL, IDENT and `(`, and nothing for MINUS —
the word "unary" does not appear in the file. `trace -1` does not parse. This is
a missing language feature, not a semantic difference.

**5b. Only `+` is type-checked.** `evaluate` (`web/interpreter.js:462`) guards
`+` carefully and then falls through to raw JavaScript operators for `-`, `*`,
`/` and the comparisons. So `true - 1` is `0` and `"a" * 2` is `NaN` — and `NaN`
is not a value in this language's type system at all, so it propagates silently
through arithmetic and comparison. Notably `true - 1 == 0` is the *exact* trap
`src/matrixlang/values.py` exists to prevent; the technical overview devotes §5.5
to it, and the reimplementation walked into the JavaScript-flavoured version of
the same hole.

**5c. Equality is `===`, so mixed types compare `false` instead of erroring.**
The spec makes cross-type comparison an error precisely so that `"1" == 1` can't
quietly be a taken branch.

**5d. Numbers are IEEE doubles.** `9007199254740993` cannot be represented, and
large products render in scientific notation — which is not valid MatrixLang
syntax, so the web IDE can print a value its own lexer could not read back. The
technical overview grounds Turing-completeness on "unbounded loops with
unbounded integer storage"; the web engine has neither, since
`web/interpreter.js:407` also caps execution at `maxSteps = 10000`.

**5e. Strings have no escape processing.** `readString`
(`web/interpreter.js:171-190`) accumulates raw characters and stops at the first
`"`. So `\n` stays two characters, and `\"` cannot escape a quote at all —
`trace "say \"hi\""` mis-lexes rather than printing `say "hi"`.

Also absent: the control-character refusal that `src/matrixlang/lexer.py:51-73`
implements and the README advertises. In a browser this is much less serious
than in a terminal, and `web/app.js:174` correctly routes every value through
`escapeHtml` before `innerHTML`, so there is no injection here. It is a fidelity
gap, not a vulnerability.

**None of this is tested.** `tests/` contains only Python. The CI workflow runs
`python -m pytest` and nothing else, so `web/` — 887 lines of JavaScript,
including a complete second interpreter — is entirely ungated. That is the
finding underneath all the others in this section: divergence is guaranteed to
accumulate, because nothing compares the two.

**Direction.** The cheapest durable fix is a differential harness — run a corpus
of `.rain` programs through both engines and assert identical output. It is
about thirty lines of Node plus a fixture directory, it catches every row of the
table above, and it turns "matching the v0.5.0 spec" from a comment into a test.
The alternative — compiling the Python to WASM, or dropping the JS engine —
is a larger decision than an audit should make.

## 6. The web glyph view corrupts comment text

**Severity: low — but it is the exact mistake the design documents reject.**

`convertToGlyphs` (`web/interpreter.js:39`) is textual substitution over source.
It correctly skips string literals and respects identifier boundaries, but it
does not skip comments:

```
source:              # a comment with trace and 5
web glyph view:      ﾒ a comment with ﾄ and ｫ
matrixlang render:   ﾒ a comment with trace and 5
```

`src/matrixlang/render.py:100-103` maps the `#` marker and leaves the text
alone, which is right: comment text is trivia, not syntax.

The reason this is worth writing down is that `docs/TECHNICAL-OVERVIEW.md`
answers "Why not just use a substitution table for the glyphs?" with exactly
this failure mode — "`x2` contains a digit; `trace "trace"` contains a keyword
inside a string" — and concludes that "the correctness comes from *where* the
substitution happens". The web implementation handles both cited examples
correctly and then misses the third case the same argument covers. It is a good
illustration that the argument was right and the enumeration was incomplete.

## 7. Documentation has drifted from the code

**Severity: low — but the drift is in the numbers the document leads with.**

`docs/TECHNICAL-OVERVIEW.md` opens by pinning itself to a measurement:

> Written against `feat/cascade-window` — 2,510 lines of source across 20
> modules, 3,514 lines of tests, 743 tests passing

Actual, at `e1af9a1`: **2,587 lines** of source across 20 modules, **3,629 lines
of tests**, **753 tests**. The module table in §3 is stale in the places the
recent work touched:

| module | table says | actual |
| --- | --- | --- |
| `interpreter.py` | 206 | 227 |
| `cascade.py` | 163 | 210 |
| `window.py` | 168 | 200 |
| `render.py` | 206 | 206 ✓ |
| `display.py` | 96 | 96 ✓ |

Two prose claims have also gone stale:

- **§3 says "Nothing may import `window`."** `src/matrixlang/cli.py:13` imports
  it, and `tests/test_architecture.py:40-43` explicitly permits that. The rule
  the test actually encodes is "nothing *in the core* may import window; the CLI
  may". The prose as written is falsified by grep, which undercuts a section
  whose whole point is that these rules are executable.
- **"No CI" appears twice as an honest limitation** (§"What would you do
  differently?" and §"Things to be honest about"). `.github/workflows/tests.yml`
  has run the suite on every pull request and every push to `main` across four
  Python versions since commit `06acdc7`. The incident described — a source
  change riding in on a documentation PR — is now the workflow's own header
  comment. The limitation was fixed and the confession was left in.

For a repository whose stated appeal is that its documentation is the record of
its reasoning, stale self-measurement is the costliest kind of rot: it is the
part a reader has no independent way to check.

## 8. Smaller things

**`CascadeWindow._closed` is write-only.** Set to `False` at
`src/matrixlang/window.py:85`, set to `True` at `:153`, read nowhere in `src/`
or `tests/`. `close()`'s docstring explains carefully that it signals execution
is over and the window stays open — which is true, but the signal has no
receiver. Finding 3 wants exactly this flag, so the fix is probably to use it
rather than delete it.

**REPL diagnostics go to stdout.** `src/matrixlang/repl.py:80-82` prints errors
to `self._out`. `README.md` says diagnostics "appear as plain text in the
window's status strip and on stderr". The README sentence is about the runner,
so this is arguably consistent — but it means `matrixlang repl < script.rain >
out.txt` captures error text into the output stream, which is the thing
`events.TextSink` is documented as protecting against ("a program whose output
is being captured should not gain a diagnostic in the middle of it",
`events.py:68-71`).

**A stray tracked file.** `:load`, zero bytes, at the repository root, committed
and in history. It looks like a shell redirect that caught a REPL command.

**The REPL re-lexes its whole buffer per line.** `repl.py:44` calls
`_open_blocks(source)` on every keystroke-line, which lexes the accumulated
buffer from the start — quadratic in block length. Irrelevant at REPL scale;
noted only because it is invisible until someone pastes something long.

## What holds up

Worth stating plainly, since the above is all defects.

The property test over 300 generated trees in three faces is doing real work,
and the mixed-face case is not decorative — glyph, ASCII and mixed source all
lex and re-parse identically in the differential runs above. The architecture
tests caught nothing here because there is nothing to catch: the import graph
matches the table exactly, and no module outside `glyphs.py` carries a katakana
literal. The control-character refusal is implemented where the technical
overview says it is, and covers strings and comments alike. Integer division
truncates toward zero, including for negatives, in both implementations. And the
purity gradient described in §5.6 is what made findings 1 and 2 measurable
without a display at all — every measurement in this document ran headless.

The defects cluster in one place, and it is the newest place: the cascade as an
output device, plus a web front end that grew alongside it without a test
harness. The language core underneath is in good shape.

## Reproducing

Baseline, and finding 1:

```bash
PYTHONPATH=src python3 -m pytest -q            # 753 passed

PYTHONPATH=src python3 -c "
from matrixlang.translit import transliterate, untransliterate
print(untransliterate(transliterate('ｱ')))"    # -> g, not ｱ
```

Finding 2 — one frame's drain against a running program:

```bash
PYTHONPATH=src python3 - <<'PY'
import threading, time, queue
from random import Random
from matrixlang.cascade import CascadeField
from matrixlang.window import drain
from matrixlang.interpreter import Interpreter
from matrixlang.lexer import lex
from matrixlang.parser import parse

tree = parse(lex('construct n = 0\ndejavu n < 400000\n  n = n + 1\nflatline\n'))
q, field, errors = queue.Queue(), CascadeField(80, 30, Random(7)), []

class QueueSink:
    def emit(self, e): q.put(e)

threading.Thread(target=lambda: Interpreter(sink=QueueSink()).run(tree),
                 daemon=True).start()
time.sleep(0.05)
t0 = time.perf_counter(); drain(q, field, errors); t1 = time.perf_counter()
print(f"drain() took {t1-t0:.2f}s against a 0.033s frame budget")
print(f"waiting={len(field._waiting)} history={len(field._history)}")
PY
```

Findings 4 and 5 — the differential harness (needs `node`):

```bash
cat > /tmp/jsrun.mjs <<'JS'

import { readFileSync } from 'fs';
```
